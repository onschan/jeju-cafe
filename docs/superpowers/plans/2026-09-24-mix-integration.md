## 2. 조작 규칙 최종안

한 동작이 트랙마다 다른 길로 가지 않게 하나로 묶었다.

| 손가락 | 무엇이 일어나나 | 숏컷을 끄면 |
|---|---|---|
| **탭** (빈 칸·추천 칸) | 고스트만 그 칸으로 간다. 짓기는 ✓ 확정뿐 | 같다 |
| **탭** (시설) | 미니 카드. 손님이 앉은 좌석이면 **「🪑 시설」 탭이 먼저**, 위 칩으로 「🙂 손님」과 오간다 | 같다 |
| **길게 누르기** (시설·빈 칸) | 방사형 4버튼. 시설이면 올리기·이동·철거·같은 것 더, 빈 칸이면 자리·정원·조명·길 | 예전처럼 **바로 들어 올리기**(이동 모드) |
| 방사형 **[이동]** | 들어 올리기와 같은 흐름 — 확정할 때 손님이 있으면 **예약**으로 넘어간다 | — |
| **두 번 탭** (시설) | 한 번에 업그레이드(트리가 있으면 다음 단계, 없으면 증축 Lv). **점유 좌석이면 확인 팝업이 이유를 붙이고 확정은 예약** | 아무 일 없음(탭 두 번) |
| **두 번 탭** (빈 칸) | 최근에 지은 시설 고스트 | 아무 일 없음 |
| **하단 바 길게 누르기** | 짓기=최근 시설 퀵바 · 카페=메뉴판 · 사람=채용 · 장부=경영 현황 | 창만 열린다 |
| **상단 바 좌우 스와이프** | 왼쪽=느리게, 오른쪽=빠르게 (스와이프 뒤의 탭은 삼킨다) | 창만 열린다 |
| **끌기** | 언제나 카메라. 고스트·옮기는 시설 위에서 길게 누른 뒤부터만 그 시설을 끈다 | 같다 |

**손님이 앉아 있을 때의 규칙은 하나다**: 어느 길로 들어와도(카드 버튼·방사형·두 번 탭) 버튼은 꺼지지 않고, 확정하면 예약이 걸린다. 급하면 카드의 「지금 바로」 — 앉은 손님을 빈 자리로 옮기고, 빈 자리가 없으면 만족 −5로 돌아간다.

설정 토글 3개(`자리 추천 보기` · `숏컷` · `맵 위 표시 최소화`)는 각자 다른 키를 쓰고 서로 간섭하지 않는다. 숏컷을 끄면 길게 누르기·두 번 탭·바 길게 누르기·상단 스와이프가 한꺼번에 예전 동작으로 돌아간다.

## 3. 카드 통합 (`MiniCard.ObjectCard`)

세 트랙이 같은 카드에 줄을 더했다. 1차 정보 3줄 + 「자세히」 규칙을 지키려고 이렇게 쌓았다.

```
[🪑 시설] [🙂 손님]        ← seatfix: 좌석 위 손님일 때만
이름 · Lv · 짓는 중/낡음    ← 1줄
▸ 자세히 (+2)              ← 입소문·시너지·명당·밤·청결은 접힘
손님이 못 와요 — 올렛길이 끊겼어요   ← ui3: 못 갈 때만 (빨간 테두리 + 「길 잇기」/「길 놓기」)
 업그레이드 ▲ …            ← fun 트리
[이동][철거][같은 것 더][이름][자세히]
예약됨 · 철거 · [지금 바로][취소]   ← seatfix: 예약이 있을 때만
손님이 앉아 있어요 · 눌러 두면 …     ← seatfix: 막혔는데 예약이 아직 없을 때만
```

- ui3 「손님이 못 가요」 칸에 있던 **[이동]은 뺐다** — 바로 아래 버튼 줄에 같은 버튼이 있어 375px에서 두 번 보였다.
- **좌석 위 손님을 탭하면 기본 탭은 「시설」로 둔다**(바꾸지 않았다). 손 플레이로 판단한 이유: ① 손님은 몇 초 뒤 떠나지만 시설은 남는다 — 오래 가는 결정은 시설 쪽이다. ② 탭하면 손님 말풍선이 이미 맵 위에 뜨므로 「손님」 탭은 상세를 볼 때만 필요하다. ③ 기본을 「손님」으로 두면 seatfix가 없애려던 「앉은 손님 때문에 못 만지는 답답함」에 탭이 한 번 더 붙는다.

## 4. 진단 일원화

`coach.diagnose`가 직원 부족을 제 나름대로 재고, 채용 화면(`staffPlan.roleNeeds`)은 `roleHeads` 인분 환산으로 쟀다. 같은 카페를 두고 다른 직종을 가리킬 수 있었다.

- `coach.ts`가 `staffPlan.roleNeeds(s)`를 그대로 인용한다. 걸림돌 문구가 채용 화면의 「지금 필요해요」 문구와 **같은 문자열**이다.
- 다음 수도 같은 말로 — `바리스타 1명` · `요리사 1명` · `홀 직원 1명` · `청소 직원 1명`.
- 근거 줄에 **「모자란 직종」** 한 줄을 더했다(채용 화면 칩과 같은 목록).
- 순서: 손님이 못 감 → 자리 → 직원 없음 → **직원 병목(roleNeeds)** → 메뉴 → 인기 → 경관 → 적자.
- 회귀 테스트: `coach.test.ts` 「진단의 직원 병목은 채용 화면의 「지금 필요해요」와 같은 판정을 인용한다」.

손 확인(1년 3월): 진단 근거 「모자란 직종 = 조리 · 홀」 ↔ 채용 화면 칩 = 요리사·홀. 일치.

## 6. 봇 밸런스 — staff2 우려 재현과 원인

staff2 보고의 「봇 5년 4년차 잔고 −482만」이 `mix`에서도 재현됐다(seed 1, **최저 잔고 −655만 · 파산**).

원인은 인건비가 아니었다. 봇 5년 seed 1은 **4년 12월·5년 1·2월과 5년 12월·6년 1·2월에 손님이 한 명도 안 왔다**. 파고들어 보니:

- 4년 12월 2일 본관이 Lv4로 커지면서 **문이 (13,13)으로 옮겨 갔는데 그 칸에 야외 테이블이 서 있었다**.
- 문이 막히면 `autoConnectDoor`가 「문 앞에 야외 테이블이 있어요」로 포기하고, 「길 잇기」도 못 쓴다.
- 여름엔 야외 자리로 버티지만, 실내 자리만 쓰는 **겨울 석 달은 손님 0**이 된다. 그 동안 인건비·유지비만 나가 잔고가 음수로 떨어졌다.

**고친 것**(`rooms.ts clearDoorFront`): 발자국 아래 올렛길을 걷어내듯(`clearPaths`), **증축·이사로 옮겨 간 문 앞 한 칸도 비운다** — 막고 있던 시설을 치우고 값을 돌려주고 알림 한 줄. 정류장·본관·샘과 길은 건드리지 않는다. 회귀 테스트는 `rooms.test.ts`.

인건비·확장 속도는 손대지 않았다. 원인이 거기가 아니었고, 문 앞을 비우자 밴드 안으로 돌아왔다.

## 9. 미해결

1. **`dopamine 3 1` 공백 16일** (기준 ≤12일). `main`도 seed 2에서 16일로 이미 못 넘긴다(seed 1만 정확히 12일). 통합으로 rng가 밀리면서 주간 이벤트 두 번이 비는 달이 생겼다. 지표를 맞추려고 진단·알림을 사건으로 세면 수치만 좋아지므로 손대지 않았다. 사건을 실제로 하나 더 놓는 패치가 따로 필요하다.
2. **본관 문 앞 규칙은 증축·이사만 막는다.** 손으로 문 앞에 시설을 놓는 것은 여전히 되고, 그러면 ui3의 ✕ 배지와 「길 잇기」로 알아채야 한다. 놓을 때 막는 게 맞는지(고스트 주황)는 다음 패치로.
3. **`ObjectCard`가 세 트랙 조건이 다 겹치면 길다.** 도달 불가 + 예약 + 트리 업그레이드가 동시에 있으면 버튼 줄이 두 번 나온다. 실제로 겹치기 어려운 조합이라(앉은 손님이 있으면 그 자리는 도달 가능) 두고 봤다.
4. **봇은 손님이 못 가는 시설을 안 고친다.** seed 1 4년차에 22개까지 쌓였다. 사람은 ✕ 배지로 알아채지만 봇은 그대로 둔다 — 봇 KPI가 실제보다 낮게 나온다.
