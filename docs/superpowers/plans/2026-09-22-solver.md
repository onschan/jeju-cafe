# 최적해 솔버 — 「프로게이머라면 했을 플레이」를 롤아웃으로 찾는 가이드 (브랜치 `solver`)

사용자 피드백(그대로): "프로게이머식 **말투**를 하라는 게 아니라, **프로게이머가 있다면 이런 플레이를 했을 거라고 알고리즘으로 최적해를 찾아서** 가이드하라는 것."

이전(`pro-guide`)의 `strategy.ts`는 입지 점수·콤보 수 같은 **휴리스틱**으로 글로우 칸과 「지금 추천 행동」을 골랐다. 이번엔 그 휴리스틱을 **후보를 줄이는 데만** 쓰고, 순위는 **결정적 sim을 실제로 굴려**(복제 상태에 행동을 적용하고 `tick`으로 H일 롤아웃) 매긴다. 근거도 시뮬 수치다: "야외 테이블 (13,13) — 14일 굴려 보니 자금 +₩42만 · 목표 +1, 2위보다 ₩9만 더".

### 1.1 점수 (`SOLVER_WEIGHTS`, 돈 단위)

점수 = Σ 가중치 × (H일 뒤 − 지금). 순위·`delta`는 **「아무것도 안 함」(저축) 롤아웃 대비**.

| 항 | 가중치 | 비고 |
|---|---|---|
| 자금 | 1 | |
| 시설 자산 (철거 환불 = 비용, 보호·방·철거비 있는 것 제외) | 0.8 | 짓는 것이 공짜가 아니게 |
| 평판 1점 | 50,000 | |
| 하루 손님 기반값 1명 (`guests.dailyGuestCount`) | 100,000 | `state.popularity`는 동네↔인기 게이지라 안 본다 |
| 메인 목표 1개 달성 | 1,000,000 | 진행 중 목표 진행률 1.0 = 400,000 |
| 적자 달 1회 | −1,500,000 | |
| 평판 20 아래로 | −3,000,000 | |
| 롤아웃 중 잔고 0 아래 | −20,000,000 | |
| runRate (끝 7일 매출 × 30/7 − 월급·유지비) 1개월분 | 1 | 지평 너머의 가치 — 투자가 H일 안에 본전을 못 뽑아도 보이게 |

### 1.2 탐색 (`bestMoves`)

1. 기준선: 아무것도 안 하고 H일.
2. 깊이 1: `pickDiverse(candidateActions(s), maxCandidates)` — 후보를 유형(좌석·담·나무·채용·홍보·도전 …)별로 돌아가며 뽑는다(좌석 후보 열 개가 채용을 밀어내던 문제). 각각 H일 롤아웃.
3. 깊이 2: 상위 `beam`(3)은 H/2일 뒤 `second`(4)개 다음 수까지 보고 최댓값.
4. anytime: `maxRollouts`(결정적)·`budgetMs`(벽시계 — 결과가 시간에 따라 달라질 수 있어 UI 워커에서만).
5. 결과: 상위 3 `{ action, score, delta:{money,reputation,goals}, why, label, cells, targets, horizon }`. 같은 상태·같은 옵션 → 같은 답(`Math.random`·`Date` 없음).

옵션: 기본 `{ beam 3, depth 2, horizon 30, maxCandidates 48, second 4, maxRollouts 200 }` · UI `{ horizon 14, maxCandidates 40, maxRollouts 80, budgetMs 4000 }` · 봇 `{ horizon 14, depth 1, maxCandidates 12, maxRollouts 12 }`.

tick 속도 2.3배: ① `path.reachMap`을 (배치 서명, 출발 칸)으로 캐시 — 시간마다 스폰이 정류장 BFS를 새로 돌렸다. ② `layoutRev.layoutSig`에서 `nextId` 제거 — 손님이 스폰될 때마다(`g${nextId++}`) 서명이 바뀌어 site·compat·reach 캐시가 전부 무효화되고 있었다. `occupy`/`vacate`가 rev를 올리므로 nextId는 중복이었다. **봇 3년 CSV(seed 1) 바이트 단위 동일** 확인. 헤드리스 3년 16.5s(전 21s).

설계 목표 「30일 롤아웃 ≤ 8ms」는 **닿지 않는다**: 프로파일이 평평하다(spawn 30% · updateGuests 25% · checkGoals 10% · 나머지 분산) — 손님 시뮬 자체가 비용이라 렌더 fx·알림 생략 플래그로는 안 줄어든다(fx는 이미 0, 알림은 하루 30건). 대신 UI 지평을 14일로, 후보 상한 40, 워커에서 4초 예산. 후속: 손님 이동을 시간 단위로 뛰게 하는 「빠른 tick」은 결과가 달라져(결정성·밸런스) 별도 검토.

## 3. 휴리스틱 봇 vs solver 봇 (3년, `pnpm headless 3 <seed> [--solver]`)

### 3.1 측정

| seed | 봇 | 1년차 말 자금 | 3년차 말 자금 | 목표 | 직원 | 3년차 월 손님 | 랭크 ★ | 최저 잔고 | 실행 시간 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 휴리스틱 | ₩540만 | ₩7,504만 | 74 | 5 | 2,294 | 8 ★4 | ₩300만 | 17s |
| 1 | **solver** | ₩2,962만 | **₩19,517만** | 30 | 3 | 2,849 | 9 ★1 | ₩495만 | 589s |
| 2 | 휴리스틱 | ₩674만 | ₩7,458만 | 72 | 5 | 2,260 | 8 ★4 | ₩319만 | 18s |
| 2 | **solver** | ₩3,045만 | **₩16,891만** | 25 | 3 | 2,301 | 8 ★1 | ₩494만 | 561s |
| 3 | 휴리스틱 | ₩677만 | **₩7,403만** | 73 | 5 | 2,289 | 8 ★4 | ₩362만 | 19s |
| 3 | solver | ₩1,470만 | ₩4,937만 | 25 | 3 | 2,222 | 8 ★1 | ₩495만 | 485s |

(solver 봇 = 5일마다 `bestMoves` 14일 롤아웃 12회 · 깊이 1, 세 seed 병렬 실행이라 시간은 서로 겹친 값. 파산 없음, 대출 없음.)

**결론**: 3년차 자금은 seed 1·2에서 solver가 **2.3~2.6배**, seed 3은 휴리스틱의 2/3. 목표 수는 세 seed 모두 휴리스틱이 **2.4~2.9배**(72~74 vs 25~30). ★는 solver가 ★1에 머문다(★ 조건은 시그니처 메뉴·가이드북 같은 solver 후보 밖 수순). 즉 「돈 버는 수」는 롤아웃이 잘 찾고, 「진행(목표·★) 수」는 14일 롤아웃으로는 못 본다 — solver 봇 테스트는 seed 1 자금만 본다.

### 3.2 해석

- **자금**: seed 1·2에서 solver 봇이 크게 앞선다. 휴리스틱 봇은 §4.6 밴드(1년차 말 ≤ 1,200만·1년차 순이익 300~800만)를 맞추려고 **일부러** 도전을 안 받고(2년차부터), 부탁도 안 받고, 저축하고, 직원을 3명까지만 두는 봇이다. solver 봇은 그런 자제가 없고 14일 롤아웃에서 자금·손님·평판이 오르는 수만 한다.
- **목표 수**: 휴리스틱 봇이 앞선다. 목표 체인은 「시설 N종」「레시피 개발」「필지」「별관」처럼 **14일 안에 돈이 안 되는** 장기 수순이고, solver는 목표 달성(+100만)·진행률(+40만)로 일부만 본다. 깊이 2·지평 30일로 늘리면 나아지지만 봇 3년이 30분을 넘는다(3년차 하루 tick 37ms).
- **직원**: 시뮬에서 채용은 30일 안에 매출을 올리지 않는다(완성 시작 상태 H=30: 바리스타 채용 자금 −67만·손님 0·평판 0). 직원의 값은 평판이 무너질 때(직원 0으로 두 달 → 평판 100→15) 비로소 보인다 — solver 봇은 평판이 떨어지기 시작하면 채용한다. **게임 밸런스 관찰**: 직원 효과(서빙 속도→만족)가 단기 지표에 거의 안 잡힌다.
- **seed 3**: 1년차부터 손님이 적게 붙어(6월 711 vs seed 1 863) 투자 수의 롤아웃 점수가 낮게 나와 저축이 이기는 달이 많았다 — 결정적이라 한 번 보수적으로 가면 계속 그렇다.
- **1년차 밴드**: solver 봇은 1년차 말 자금이 밴드(≤ 1,200만)를 넘긴다(1,470만~3,045만). 밸런스 테스트(`balance.test.ts`)는 휴리스틱 봇 기준 그대로 두고, solver 봇은 `solverBot.test.ts`(1달 결정성·파산 없음은 항상, 3년 비교는 `SOLVER_BOT=1`일 때만 — 10분 남짓).

## 5. 한계·후속

1. **근시안**: 지평 14일. 장기 해금 체인(랭크·★·필지·별관)은 안 보인다. 목표 가중치로 일부 보정.
2. **잡음**: 같은 행동이라도 rng 흐름이 갈려(손님 스폰 순서) 후보 간 차이가 수만 원이면 잡음일 수 있다. 결정적이라 답은 늘 같지만 「최적」이 아닐 수 있다. 후속: 같은 후보를 2~3개 rng 시드로 평균(비용 ×n).
3. **후보 범위**: 경로 시설(올레 표식·셔틀·선착장 — 길 잇기가 따로 필요)·별관·본관 이동·철거·메뉴 내리기·레시피 개발·팝업·라이벌 대결·응모권은 후보에 없다. 휴리스틱 봇이 하는 이런 수는 solver 봇이 못 한다.
4. **성능**: 30일 롤아웃 95ms(초반) — 설계 목표 8ms의 12배, 3년차엔 하루 37ms라 14일에 0.5s. UI는 워커라 체감 없지만 후반엔 4초 예산 안에 후보 8~10개만 본다. 헤드리스 solver 봇 3년 8~10분.
5. **키 만료**: 자금 버킷(1,000만 아래 10만·1억 아래 100만·그 위 1,000만)을 넘거나 배치·날·직원·메뉴판·도전·홍보가 바뀔 때 결과가 만료돼 워커가 다시 돈다(1~4초).
6. 대사 근거 줄은 24자 규칙(json 원문 기준)을 넘을 수 있다 — 대화창은 줄바꿈된다.
