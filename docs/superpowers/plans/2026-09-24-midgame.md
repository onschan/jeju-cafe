# 중반 공백(700만 구간)·응모권 용도·좌석 수요 안내 (트랙 econ2)

사용자 피드백 3개를 그대로 옮긴다.

1. 「명당 다 짓고 700만 원 구간이 굉장히 할 게 없다. 신규 메뉴를 늘릴 수 있는 것도 아니고, 신규 직원을 채용할 수 있는 것도 아니고.」
2. 「응모권은 도대체 뭐 어쩌라는 건지 모르겠다.」
3. 「테이블은 각 구간이나 홍보 기간당 몇 개나 필요한 건지 모르겠다.」

코어 원칙 #1(다음 단계가 항상 코앞)·#2(보상 층) 기준으로 셋 다 「수치로 보이게」 고쳤다.

## B. 응모권이 뭐 하는 건지 보이게

전: 응모권은 상단에 안 보이고, 장부에 「상점」·「응모권」 두 탭이 같은 화면이며, 상품표는 「강화 아이템 10%」처럼 무엇을 받는지 알 수 없었다.

- **상단 바 응모권 칸**: 응모권이 있거나 이달 무료 뽑기가 남았을 때만 나온다. 탭하면 바로 장부 › 응모권. 무료가 남았으면 배경이 금색 + 「!」.
- **뽑기 탭**: 큰 뽑기 버튼(56px)을 맨 위로 올렸다. 그 아래 **「지금 나올 수 있는 것」 3개** — 상품마다 지금 상태에서 실제로 받는 것을 쓴다(「돈 · ₩50,000 20%」「연구 · 연구 +10 15%」「재료 상자 · 재료 8개 15%」). 「▼ 이번 회차 상품 8가지」를 펴면 등급별 확률 전부.
- **상품 풀 정리**: 농원이 하나도 없으면 씨앗은 심을 데가 없는 죽은 상품이다 → **재료 상자로 바꿔 주고, 미리 보기의 이름도 바뀐 쪽을 쓴다.** 「꽝」의 설명은 「아무것도 없어요」.
- **얻을 때 안내**: 응모권을 받는 메시지 줄에 「· 장부 › 응모권에서 뽑아요」를 **처음 3번만** 붙인다 (`ticketHint`, `state.ticketHints`).

## C. 테이블이 몇 개 필요한가

`guests.ts`에서 좌석 상한을 빼고 수요를 다시 센다.

```
uncappedDailyGuests(state, popBonus = 0)   // dailyGuestCount의 min(좌석 × 6, …) 앞부분
seatsNeeded(state) -> { now, promo, have, short }
```

- `now` = ⌈수요 / 자리당 6명⌉ — 지금 인기·명소·경로·홍보·계절·평판을 그대로 반영한다.
- `promo` = 비어 있는 기간형 홍보 칸을 다 채웠다고 칠 때의 수 (`PROMO_POP_PER_SLOT = 60` = 대표 홍보 allDelta 5 × 인기 상위 12종).
- `dailyGuestCount`는 이제 `min(좌석 × 6, uncappedDailyGuests)`로 정리됐다 — 계산식은 한 곳에만 있다.

보이는 곳:

- **매력도 카드 맨 위**: 「지금 손님엔 자리 6개면 충분 / 지금 4개 · 홍보 중엔 9개」, 모자라면 빨간 테두리로 「자리 2개가 모자라요」.
- **시설 카드(자리류)**: 「자리 4/6 · 2개 더 · 홍보 중엔 9개」.
- **우리 카페 진단**: 3줄 평가가 「이번 달 손님 n명 · 자리 4/6개」, 걸림돌이 「자리 2개가 모자라요 (대기 이탈 n명)」로 구체 수치가 되고, 근거 표에 「필요한 자리 — 지금 6개 · 홍보 중 9개」 줄이 생겼다.
