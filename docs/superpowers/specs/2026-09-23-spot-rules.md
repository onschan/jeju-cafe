# 명당 규칙·효과·피드백 + 요금 보상 곡선 (spot2)

사용자 피드백 다섯 가지를 고친 기록. 코어 원칙 #3(발견의 재미)·#6(3초 규칙)을 기준으로 삼았다.

| # | 피드백 | 원인 | 고친 것 |
|---|---|---|---|
| 1 | "명당 조합에 파라솔 같은 게 왜 들어가 있나 — 업그레이드하면 풀리는 거 아님?" | 명당 조각이 **시설 id**라, 자리를 파라솔 → 테라스로 올리면 명당이 깨졌다 (설계 모순) | 업그레이드 트리에 있는 조각을 **트리 통째로 한 종류**로 센다 (`cornerKinds.ts`). 올리면 오히려 효과가 세진다 |
| 2 | "명당 근처에 테이블 설치하면 뭐가 좋은지 모르겠다" | 효과가 화면 어디에도 안 보였다 | 자리 카드 「명당 꽃길 옆 · 요금 +12% · 만족 +5」, 조각 카드 「돌봐 주는 자리 n곳 · 오늘 매출 ₩n」, 고스트 미리 보기 |
| 3 | "명당 피드백은 바로바로 됐으면" | 완공돼야 알 수 있었다 | 마지막 조각을 놓는 **순간** 「공사가 끝나면 꽃길 완성」 + 팻말 반투명 미리 표시 |
| 4 | "돌담 생긴 것 때문에 뭐 어쩌라는 건지 모르겠다" | `wind` 값이 시뮬에서 **아무 데도 안 쓰이고 있었다** | 북서쪽 쐐기에 돌담 둘이면 겨울 야외 자리 만족 +8. 카드 설명·고스트 반경·줄 미리 보기로 보이게 |
| 5 | "시너지나 명당 배치나 자리 수준이 좋을수록 받는 요금이 좀 더 많이 좋아지면" | 자리 점수가 요금에 거의 영향이 없었다(전망 1당 +4%, 최대 +20%) | 요금 보상 곡선을 세게 + 배수를 **fee.ts 한곳**으로 모았다 |

## 1. 조각은 「종류」다 (업그레이드해도 안 깨진다)

- 종류는 표로 적지 않고 `upgrade_tree.json`에서 자동으로 만든다 — **자리·벤치·불빛·꽃·매대** 다섯(트리 다섯 개).
- 트리 밖 시설(돌담·돌하르방·수국·삼나무·물허벅·표지판…)은 업그레이드로 바뀔 일이 없으니 **시설 그대로** 둔다. 명당마다 고유한 맛이 남는다.
- 트리의 마지막 단계(오름 뷰 벤치·연못·도대불)도 더 올라갈 데가 없어 깨지지 않으므로 그 자리를 지키는 조각으로 그대로 쓴다.
- **상위 단계 보너스**: 조각 단계 합마다 요금 +3%p · 입소문 +10%(상한 +50%). 파라솔로 올리면 명당이 더 좋아진다.

> 처음엔 `seat`·`bench`·`light`·`flower`·`tree`·`wall`·`sign`·`stone` 같은 **넓은** 카테고리로 만들었는데,
> 명당이 우연히 겹쳐 완성되면서 봇 3년 KPI가 무너졌다(목표 45 → 26 · 3년차 자금 ₩2,620만 → ₩337만 · ★3 → ★1).
> 넓은 카테고리는 퍼즐을 없애고 등급·해금을 앞당겨 봇이 감당 못 할 투자를 하게 만들었다. 그래서 **업그레이드로 실제로 깨지는 것(트리)만** 종류로 묶었다.

## 2. 효과가 닿는 곳

| 값 | 닿는 곳 |
|---|---|
| 요금 | 반경 2 안의 **자리**(좌석)와 요금 받는 시설만 |
| 입소문 | 반경 2 안 전부 (명당이 있는 마당 자체가 소문난다) |
| 만족 | 태그 맞으면 +5, 전체 대상 +3 |
| 관광객 가중치 | 태그 맞는 명당마다 ×1.2~1.3 |

## 3. 요금 보상 곡선 (fee.ts)

배수를 만드는 것이 한 파일에 모였다 — 흩어져 있으면 카드 숫자와 실제로 받는 값이 갈라진다.

| 항목 | 전 | 후 |
|---|---|---|
| 자리 | `1 + 0.04 × 전망(0~5)` → 최대 +20% | `1 + 0.04 × 자리 점수(0~10)` → 최대 **+40%** (8점이면 +32%) |
| 명당 | +5% / +8% / +10% | **+12% / +18% / +24%**, 조각 단계마다 +3%p, 합산 상한 **+30%** |
| 거리 | +5% | **+8%** |
| 총 배수 상한 | 없음(흩어져 있었다) | **×2.0** — `fee.ts FEE_MULT_CAP` 한 곳 |

곱셈으로 쌓인다: 자리 1.40 × 명당 1.30 × 거리 1.08 ≒ 1.96 — 다 갖춘 자리만 상한에 닿는다.

### 기본 메뉴 값 조정 (밴드 맞추기)

요금 배수가 세지면서 봇 1년차 순이익이 밴드(500만~1,200만)를 넘었다. 손님 수·고정비가 아니라 **기본 메뉴 값**으로 맞췄다 —
음료는 내리고(1년차는 음료만 판다) 디저트·식사는 올려(3년차 정체 해소) 잘 꾸민 카페와 안 꾸민 카페의 격차는 그대로 뒀다.

| 분류 | 배수 | 예 |
|---|---|---|
| 음료 | ×0.94 | 아메리카노 3,200 → 3,000 · 카페라떼 4,000 → 3,800 · 감귤주스 4,500 → 4,200 |
| 디저트 | ×1.06 | 치즈케이크 5,500 → 5,800 · 당근케이크 6,000 → 6,400 |
| 식사 | ×1.06 | 계란 샌드위치 5,000 → 5,300 · 당근 수프 6,500 → 6,900 |

## 4. 돌담의 쓸모

`wind` 값은 `isSheltered`만 쓰고 있었고, 그걸 부르는 곳이 시뮬에 없었다 — 돌담은 경관 +1짜리 장식이었다.
이제 **겨울에만**, 자리 북서쪽 쐐기(1~3칸, |dx−dy| ≤ 1)의 바람막이 합이 3 이상이면 그 자리 만족 +8.
돌담은 바람 2라 **둘을 이어야** 막힌다 — 고스트가 그 순간을 짚어 준다("자리 3곳 겨울 바람을 막아요").
