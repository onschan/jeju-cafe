### 러시를 세 판 해 보고

**판 1 — 새 게임 (좌석 6, 직원 0)**
```
0.8s  줄=0        ← 11초까지 화면에 아무도 없다
11.3s 줄=1
15.0s 줄=0 받음=1   ← 자동 착석
22.5s 줄=1
30.0s 줄=0 받음=2   ← 자동 착석
33.8s 줄=1
45.0s 줄=0 받음=4   ← 자동 착석
무조작 결과: C · 41점 · 놓침 0
줄이 비어 있던 시간 22.5초 / 45초 (50%)
```

**판 2 — 4년차 세이브 (좌석 38, 직원 3), 손으로 6번 탭**
```
0~14초   줄 0→10   (아무도 안 앉는다)
15초     줄 0, 받음 11, 점수 225   ← 자동 착석
16~29초  줄 0→10   (아무도 안 앉는다)
30초     줄 0, 받음 22, 점수 460   ← 자동 착석
31~44초  줄 0→10
45초     줄 0, 받음 33, 점수 703   ← 자동 착석 + 내 탭
결과: A · 703점 · 놓침 3
```
점수가 **15초마다 한 번씩 계단으로 뛴다.** 그 사이 14초는 줄만 길어지고 아무 일도 없다.
「러시 때 아무도 안 움직인다」는 걸음 속도만의 문제가 아니었다. **15초 동안 진짜로 아무도 안 앉는다.**

**판 3 — 27일 대항전 날** — 러시 화면과 **완전히 같았다**. 상대 카페 이름도, 점수 비교도 안 나왔다.

**무조작 vs 완벽 조작** (`scripts/_rushskill.ts`)

| 세이브 | 무조작 | 완벽 조작 | 탭 | 놓친 손님 |
|---|---|---|---|---|
| 새 게임 | **C** 41점 | B 58점 | 3회 / 45초 | **0 → 0** |
| 4년차 | **B** 599점 | S 1017점 | 28회 / 45초 | **3 → 3** |

점수는 +41%·+70% 바뀌니 스펙 §7-2는 통과한다. 하지만 **놓친 손님이 똑같다.**
잘해도 못해도 세상에서 달라지는 건 글자 하나(B/S)와 응모권 1장뿐이다. 이건 걸린 게 없는 점수판이다.

그리고 **「잘 맞는 자리 보너스」(+8점, 기본 점수 10점과 맞먹는 최대 항목)가 화면에 전혀 안 보인다.**
`rushBridge.ts:seatFits`는 export만 돼 있고 `GameView.ts`·`App.tsx` 어디서도 안 쓴다.
초록 칸이 전부 똑같이 생겼으니 최적 플레이는 **「제일 가까운 초록을 빨리 누르기」** — 판단이 없는 반사 신경 시험이다.

## §5 P0 — 이것 없으면 게임이 아니다

### P0-1. 러시가 플레이어 없이 굴러간다

- **증상** 4년차 무조작 = **B등급 599점**, 놓친 손님 3명. 손으로 28번 눌러도 놓친 손님은 **똑같이 3명**. 점수는 15초마다 계단으로만 오른다.
- **원인** `src/sim/rush.ts`
  - `RUSH_AUTO_PERIOD_MS = HOUR_MS`이고 `RUSH_RUN_MS = 3 * HOUR_MS`라 `autoSeat`이 **정확히 3번** 돈다.
  - `autoSeat()`은 한 번 돌 때 `while` 루프로 **줄 전체**를 빈 자리가 떨어질 때까지 앉힌다.
  - `runRush()`가 `autoSeat`을 **무조건** 부른다 — `rushAutoOn()`(플레이어 설정)은 `rushBridge.ts`에 있는 HUD 라벨용이고 sim은 안 본다.
- **고칠 곳**
  1. `runRush()`에서 `autoSeat` 호출을 **플레이어가 「자동 진행」을 켠 경우에만**으로 바꾼다. 설정값을 `state`로 옮겨라(`state.rushAuto`), 지금은 localStorage에만 있어 sim이 못 읽는다.
  2. 자동을 껐을 때는 `tickPatience`가 실제로 사람을 내보내야 한다. 인내 20~40초 vs 자동 15초라 지금은 **만료가 한 번도 안 일어난다**.
  3. 봇·헤드리스는 `resolveRushAuto()`를 그대로 쓰면 되므로 KPI 밴드는 안 흔들린다.
- **어떻게 확인** `scripts/_rushskill.ts` 재실행 → **무조작이 C 이하**, 그리고 **놓친 손님이 무조작 ≫ 완벽조작**이어야 한다. 지금은 3 = 3.

### P0-2. 조작에 판단이 없다 — 「잘 맞는 자리」가 안 보인다

- **증상** 러시 중 초록 칸이 전부 똑같다. 어느 칸이 +8점인지 알 방법이 없다.
- **원인** `src/ui/rushBridge.ts:seatFits`가 어디서도 호출되지 않는다. `rushMarks()`가 돌려주는 `kind`는 `'ok' | 'no' | 'urgent'` 세 가지뿐이고 `GameView.ts:774~783`은 그 세 가지만 칠한다.

### P0-3. 초반 러시에 손님이 없다

- **증상** 새 게임 첫 러시: 45초 중 **22.5초(50%)가 빈 화면**, 도착 4명, 줄 최대 1명. 결과는 C(평판 −2).
- **원인** `rushArrivals()` = `min(plain * RUSH_SPAWN_MULT, rushCapacity * RUSH_ARRIVAL_OVER)`.
  `rushCapacity = totalSeats * 0.5 + staff * 2` — 좌석 6·직원 0이면 capacity 3, arrivals 4.
  그리고 첫 판 등급 문턱이 `RUSH_EXPECT_PER_GUEST = 27`인데 자동 착석 한 명이 8점이라 C가 수학적으로 확정된다.
- **고칠 곳**
  - `rushArrivals()`에 **하한 8명**을 둔다(줄 상한과 별개로). 첫 러시가 「몰아친다」로 느껴져야 한다.
  - 첫 러시는 `RUSH_REWARDS.C.reputation = -2`를 면제한다(`finishRush`에서 `rushGrades` 합계가 0이면 감점 없음).
  - `seatsShort()`(`rushBridge.ts`)가 **금요일 예고 때** 뜨게 한다. 지금은 토요일 11시에 처음 알려 주고, 자리를 늘리면 필요 수도 같이 올라(`queueSizeFor`가 `rushCapacity` 기반) 만족이 안 된다 — 필요 수를 **고정값(좌석 8)** 으로 바꿔라.
- **어떻게 확인** `scripts/_rushprobe.ts new` → 「줄이 비어 있던 시간 ≤ 10초 / 45초」, 「줄 최대 ≥ 4」.

### P0-4. 러시 해금이 저절로 열린다

- **증상** 봇 3년 성적 **S 0 · A 17 · B 101 · C 26**. 러시 목표 7개(g27·g31·g35·g38·g40·g41·g43)가 조건 B×1·3·6·10·15·20 + A×1 — **전부 무조작으로 채워진다.**
- **원인** `src/data/goals.json`의 문턱이 「무조작 = B」라는 사실과 어긋난다. 덤으로 **g27과 g35가 같은 `omegi_stall`을 준다**(중복 해금).
- **고칠 곳**
  - P0-1을 고치면 무조작이 C가 되므로 B 문턱이 다시 의미를 갖는다. 그 위에 **A·S 문턱을 섞어라**: g31·g38은 A, g41은 S로.
  - g35의 `omegi_stall`을 다른 시설로 교체.
  - `scripts/validate-goals.ts`에 「같은 시설을 두 번 주는 목표」 검사를 넣는다.
- **어떻게 확인** `npx tsx scripts/headless.ts 3 1` 뒤 세이브의 `rushGrades`로 목표 달성 수를 세서, **무조작 봇이 러시 목표 7개 중 2개 이하**만 열어야 한다.

### P0-5. 튜토리얼이 이미 한 일을 다시 시키고 게임을 멈춘다

- **증상** 2일차 6시, 이미 3분 전에 올린 아메리카노를 두고 **「메뉴판이 비었구나 · 아메리카노부터 올려 보라」**가 뜨며 `speed = 0`. 게임이 40초 멈췄다.
- **원인** `src/sim/tutorial.ts:checkTutorial()` — `dialogueSeen(state, step.id) && step.done(state)` 둘 다여야 step++ 한다. `step.done(s)`가 **이미 true여도 대사를 먼저 띄운다**. 거기에 `stepGapPassed()`(`TUTORIAL_STEP_GAP_DAYS = 1`)가 붙어 15단계가 최소 15게임일에 걸쳐 끌린다.
- **고칠 곳**
  - `currentTutorialStep()`이 `step.done(state)`가 이미 true인 단계는 **대사 없이 조용히 넘기게** 한다(`checkTutorial`에서 `dialogueSeen` 조건을 「done이 이미 참이면 면제」로).
  - STEPS를 15 → 5로 줄이고(§3), `TUTORIAL_STEP_GAP_DAYS`를 0으로.
- **어떻게 확인** `src/sim/__tests__/tutorial.test.ts`에 「단계 조건을 미리 만족시킨 상태로 하루 넘기면 그 단계 대사가 안 뜨고 step이 오른다」 테스트 추가.

## §7 측정 구멍 — 실시간 문제를 어떻게 자동으로 잡나

### 왜 안 잡혔나

1. **헤드리스가 실시간 경로를 안 탄다.** `scripts/headless.ts`·`showcase.ts`·`bot.ts`는 `tick(s, DAY_MS)`로 하루를 한 번에 민다. `rushTimeScale()`은 `dtMs > RUSH_REALTIME_DT_MAX(100)`이면 1을 돌려주므로 **감속 코드가 아예 실행되지 않는다.** 걸음 속도 버그가 안 잡힌 이유가 이것이다.
2. **테스트가 「빈 시간」을 안 잰다.** `src/sim/__tests__/rush.test.ts`·`src/ui/__tests__/rush.test.ts`의 `waitQueue()`는 `for (i < 30 && queue.length === 0) stepRush(s)` — **줄이 빌 때까지 건너뛴다.** 「몇 초 동안 비어 있었나」가 측정 대상에서 빠져 있다.
3. **§7-2 테스트가 점수만 본다.** `rush.test.ts:333` 「조작이 점수를 20% 이상 바꾼다」는 `rs.score / ra.score >= 1.2`만 확인한다. **무조작 등급이 무엇인지**(B), **놓친 손님이 달라지는지**(안 달라짐)는 안 본다.
4. **`pnpm dopamine`은 「알림 수」를 센다.** 알림은 넘치는데(월초 21탭) 할 일이 없다 — 이 지표로는 구분이 안 된다.

### 넣을 것

**(1) `scripts/rush-density.ts` — 러시 밀도 회귀 (CI 필수)**

이번에 쓴 `scripts/_rushprobe.ts`를 정식화한다. 새 게임 / 1년 / 3년 세이브 각각에 대해 `stepRush`를 끝까지 돌리며 매 스텝 기록하고 다음을 단언한다.

| 지표 | 문턱 |
|---|---|
| 줄이 0명인 시간 | **≤ 45초의 20%** (지금 새 게임 50%) |
| 줄 최대 길이 | **≥ 4** (지금 새 게임 1) |
| 한 번에 앉는 최대 인원 | **≤ 3** (지금 11 — 자동 착석이 줄을 통째로 비우는지 잡는 지표) |
| 무조작 등급 | **C 이하** (지금 4년차 B) |
| 탭 기회 수 (줄에 손님이 있고 빈 자리가 있는 스텝 수) | **≥ 20** |

**(2) `scripts/rush-skill.ts` — 실력 차이 (CI 필수)**

이번에 쓴 `scripts/_rushskill.ts`를 정식화. 세 정책(무조작 / 무작위 탭 / 최적 탭)으로 같은 세이브를 돌려서:

- 점수: 최적 ≥ 무조작 × 1.5
- **놓친 손님: 무조작 ≥ 최적 + 3** ← 지금 빠진 것. 「잘하면 사람을 덜 놓친다」가 성립해야 러시가 게임이다
- **무작위 탭 < 최적 탭 × 0.85** ← 「어느 칸을 누르나」가 판단이어야 한다(P0-2)

**(3) `src/ui/__tests__/rushRealtime.test.ts` — 실시간 경로 테스트**

`tick(s, dt)`를 **dt = 16ms로 반복 호출**해서 `rushTimeScale`이 실제로 걸리는 경로를 탄다. 단언:

- 3배속에서 `phase === 'run'` 총 실시간이 **45초 ± 3초** (`RUSH_RUN_SECONDS`)
- `phase === 'ready'`가 **20초 ± 2초**
- 그 동안 손님·직원의 **이동 거리 합이 0보다 크다** ← 걸음 속도 버그를 잡는 단언. `rushWalkMult` 회귀가 여기서 걸린다

**(4) `pnpm dopamine`에 「빈 시간」 열 추가**

지금은 사건 수만 센다. **「플레이어가 누를 것이 화면에 하나도 없던 연속 시간의 최댓값」**을 하루마다 재서 표에 넣는다. 문턱: 게임 시간 하루 안에서 **2분 이하**(core-principles 개발 규칙).

**(5) 튜토리얼 정합 테스트**

`src/sim/__tests__/tutorial.test.ts`에 「모든 단계에 대해, `done` 조건을 미리 참으로 만든 뒤 하루를 넘기면 그 단계의 대사가 뜨지 않고 step이 오른다」를 STEPS 전체에 대해 돌린다. P0-5가 다시 안 생긴다.

**(6) `validate-goals.ts` 확장**

- 같은 시설을 두 번 주는 목표 검사 (지금 g27·g35가 `omegi_stall` 중복)
- **무조작 봇 3년 세이브의 `rushGrades`로 러시 목표를 채점해서, 2개 넘게 열리면 실패** — 「실력이 해금 조건」이 지켜지는지 자동으로 본다
