### 2.3 배치 가이드 UX

솔직히 **7편 중 어느 것도 "최적 배치 추천"을 보여 주지 않는다.** 카이로 게임에는 그런 기능이 없다. 대신 **간접 근거** 3개만 건졌다:

- v4 t=04:49 시설 정보 카드 — 그 시설 하나의 〈가격·품질·매력·Lv·다음 레벨까지 N명〉. **"이 시설이 지금 얼마나 일하고 있나"를 한 카드에 접어 둔다.**
- v1 t=00:18 매출 기여 TOP4 — **전체 중 누가 버는지 4개만** 잘라 보여 줌.
- v1 t=00:05 「가게 모습」 — 시설 위에 `MAX` 뱃지가 떠서 **더 못 키우는 것**을 한눈에 구분.

→ 결론: **우리 solver는 원본 게임보다 앞선 기능이다.** 베낄 대상이 없으므로 위 3개의 "밀도 낮추는 방식"만 훔치고(TOP N만·카드에 접기·뱃지), 나머지는 우리가 설계한다. 이 항목은 **영상 근거가 약하다는 점을 명시**한다.

### 2.4 정보 밀도를 줄이는 법 (4편 공통)

1. **상시 지표는 2~3개만.** v7은 `집세·쾌적도` 둘. v1 하단은 `손님·건물·가게인기` 셋. 우리 `AppealPanel`이 이미 3개(인기·경관·서비스)로 맞췄는데, HUD·창마다 또 다른 지표가 붙는 게 문제.
2. **나머지는 "볼 때만" 카드로.** v4 시설 정보, v1 가장 맛있는 요리 — 전부 탭해야 나오는 단일 카드.
3. **리스트는 TOP N + 페이지네이션.** v1 `요리 목록 1/12`, v4 `게임 내용 선택 2/2`, v1 매출 TOP4.
4. **판단에 필요한 숫자는 결정 창 안에 넣는다.** v3 t=00:34 — 도전 창에 4스탯을 같이 띄워서 창을 옮겨 다닐 필요가 없다. **우리 배치 추천도 이 원칙을 따라야 한다.**
5. **반복 연출은 스킵 가능해야 한다.** v4 t=08:46 자막이 카이로 게임의 대표 단점으로 지목한 지점. 대회를 연 2회 넣으면 **반드시 스킵/빨리감기**를 넣는다.

항목 점수 (0~100으로 정규화):

```
항목점수(k) = clamp(0, 100,
    메뉴스탯(k)                          // menuStatsOf — 토핑·콤보·개발 보너스 포함
  + 직원스탯보정

  + 연수보정
  + 재료보정

직원스탯보정 = (직원.stats.skill / 100) × 20      // 맛·향·외관

             = 서비스 연수 이력 1회당 +4 (상한 +12) — 스토리
재료보정     = 제출 메뉴 재료 중 농원 수확(storage) 비율 × 10   (0~+10)
```

#### 3.1.3 luck.ts 연동 (대박/중박/쪽박)

**새 확률표를 만들지 않고 `LuckTask`에 `'contest'` 하나만 추가**한다.

- **참가상**은 항상 준다 (v5 "참가상으로 천연 수목 10개"). 져도 빈손이 아니다.

실패(4위) 시:

| 손실 | 값 |
|---|---|
| 참가비 | 전액 손실 |
| 평판 | **−1** (쪽박이 겹치면 −3) |
| 직원 기력 | −15 (쪽박이면 −35) |
| 직원 경험치 | **+3** (1~3위는 +8/+6/+5) |
| 대사 | v3처럼 직원이 한 줄 — "다음엔 꼭…" |

연간 최대 영향: 2회 × 1위 = 상금 최대 ₩1,500만, 유입 ×1.25가 120일. 3년 자금 밴드를 깨지 않도록 **참가비를 그대로 상금 스케일로 쓰는** 구조를 택했다(순손익 +4배). 봇 3년 KPI 밴드 재측정 필요 — §4 트랙 A의 완료 기준.

#### 3.3.2 헷갈리는 용어·중복 지표 정리표

| 지금 | 문제 | 조치 |
|---|---|---|

| `rank` (1~10, `RANK_THRESHOLDS`) / `grade` (1~5, `GRADE_REQS`) / `star` (★) | **3중 진척 지표.** 플레이어가 셋을 구분 못 함 | **`rank` 표시 제거.** 내부 계산(해금 트리거)은 유지하되 UI에서 숫자를 안 보여 준다. 남길 것은 **등급(1~5)**과 **★** 둘. 「랭크 업」 알림은 **「새 시설이 열렸다」** 문구로 대체 |

### 3.4 직관성 — 「오늘 할 일」

#### 3.4.1 상단 1줄 + 탭하면 3개

HUD 바로 아래 **고정 1줄** (`MessageLine` 위):

```
오늘 할 일 ▸  야외 테이블을 (12,9)에                        [ 2 ]
```

- 왼쪽: **가장 값진 1수의 label** (`SolverMove.label`). 이미 `hints.ts idleHint`가 같은 값을 쓰고 있다 — **로직 재사용, 노출만 상시로**.
- 오른쪽 `[ 2 ]`: 대기 중인 다른 제안 수. 0이면 칩을 안 그린다.
- **탭 → 시트 3줄** (v1 「매출 기여 TOP4」의 "상위 N만" 원칙):

| 줄 | 출처 | 형식 |
|---|---|---|
| 1 | `cachedMoves` 1위 | `야외 테이블 (12,9) · 14일 뒤 +42만` + 「하기」 버튼 (누르면 해당 UI로 글로우 이동 — `SolverMove.targets` 그대로) |
| 2 | 진행 중 목표/부탁/월간 과제 중 **가장 가까운 것** | `「손님 200명」 까지 34명` |
| 3 | 경고가 있으면 경고, 없으면 solver 2위 | `평판 28 — 이대로면 ★가 내려간다` |

- **3줄 고정.** 더 많아도 안 보여 준다.
- 우선순위: ①파산/평판 경고 → ②대회 접수 마감 3일 이내 → ③solver 1위 → ④목표.
- 아무것도 없으면 줄 전체가 사라진다 (빈 UI를 남기지 않는다).
